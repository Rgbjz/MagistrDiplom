# Модуль адаптивного навчання

Документ описує модуль адаптації LMS: модель студента, алгоритм персоналізації навчального контенту, адаптивне формування тестів, A/B-експеримент і журнал подій. Код: `backend/src/modules/adaptive/` (чисті функції — `adaptive.algorithm.ts`, сервіс і API — `adaptive.service.ts`, `adaptive.controller.ts`), інтерфейс — `frontend/src/components/adaptive/`.

## 1. Підхід

Система поєднує два класичні підходи адаптивного навчання:

- **модель знань за темами (overlay model)** — для кожної теми курсу (розділу) зберігається оцінка засвоєння, яка оновлюється після кожного навчального доказу (відповідь на питання, оцінка роботи, проходження уроку);
- **психометрична модель Раша з онлайн-калібруванням Ело** — рівень підготовки студента θ і складність кожного питання b лежать на одній логіт-шкалі, що дає змогу добирати питання потрібної складності.

Обрано експоненційно зважене ковзне середнє (EWMA) як основну модель засвоєння, а не Bayesian Knowledge Tracing (BKT). Причини: BKT потребує оцінки чотирьох параметрів (P(L₀), P(T), P(G), P(S)) для кожної навички за історичними даними, яких у новому курсі немає; EWMA має один інтерпретований параметр α, працює з частковими балами (s ∈ [0,1]), а не лише з бінарною правильністю, і природно поєднує різнорідні докази (тести, лабораторні, уроки) через ваги. BKT залишається напрямом розвитку, коли накопичиться історія.

## 2. Модель студента

### 2.1 Засвоєння теми (EWMA)

Для пари (студент, тема) зберігається засвоєння m ∈ [0,1] і кількість доказів n. Початкове значення m₀ = 0,5 (n = 0 — «ще немає даних»).

Після кожного доказу:

```
m ← m + α · w · (s − m),   m ∈ [0,1]
```

- s ∈ [0,1] — нормований результат доказу:
  - відповідь на питання: `earned / maxPoints` (часткові бали враховуються);
  - лабораторна: `score / maxScore`;
  - завершений урок: 0,7 (свідчення залученості, а не знання);
- w — вага доказу: питання 1,0 × коефіцієнт складності (рівень 1 → 0,8; 2 → 1,0; 3 → 1,2), лабораторна 0,8, урок 0,25;
- α = 0,3 — швидкість навчання моделі.

Рівні теми за порогами курсу τ (поріг засвоєння, за замовчуванням 0,6) і ρ (поріг прискорення, 0,85):

| Умова | Рівень |
|---|---|
| n = 0 | ще немає даних |
| m < τ | потребує повторення |
| m ≥ ρ і n ≥ 3 | засвоєно |
| інакше | в процесі |

### 2.2 Рівень студента і складність питань (Раш + Ело)

Імовірність правильної відповіді студента з рівнем θ на питання складності b:

```
P = σ(θ − b) = 1 / (1 + e^{−(θ − b)})
```

Початкова складність питання задається викладачем рівнем 1..3 → b₀ = −1, 0, +1. Після кожної оціненої відповіді r ∈ [0,1]:

```
θ ← θ + K_θ(n) · (r − P),     K_θ(n) = 0,6 / (1 + 0,05·n)
b ← b − K_b(k) · (r − P),     K_b(k) = 0,3 / (1 + 0,05·k)
```

де n — кількість відповідей студента, k — кількість відповідей на це питання. Кроки зменшуються з накопиченням даних (оцінки стають стабільнішими). Значення обмежені |θ|, |b| ≤ 4.

### 2.3 Перерахунок з історії

`replayHistory(events)` відтворює модель курсу з усієї історії в хронологічному порядку тими самими кроками, що й онлайн-оновлення (тому перерахунок = інкрементальним оновленням). Історія: відповіді спроб (`AttemptQuestion`), старі спроби без пострічкових записів (`UserAnswer`, правильність вибору), оцінені роботи (`Submission`), завершені уроки (`LessonProgress`).

## 3. Алгоритм персоналізації (рекомендації)

Кандидати дій:

| Тип | Умова | Ціль |
|---|---|---|
| REVIEW | тема «потребує повторення» | 2 уроки теми: спершу з найбільшою часткою помилок у тесті, потім незавершені |
| RETRY_TEST | тема «потребує повторення» і має тест | адаптивне перескладання тесту теми |
| NEXT | перший незавершений урок, якщо попередні теми не слабкі | наступний урок курсу |
| SKIP_AHEAD | тема «засвоєна», а уроки ще лишились | позначити решту уроків теми необов’язковими, перейти до наступної теми |
| CHALLENGE | тема «засвоєна» і має тест | складніші питання |
| DEADLINE | незданий дедлайн ближче ніж 7 днів | здати роботу |

Пріоритет (пояснюваний, детермінований):

```
priority = base(type) + w_gap·max(0, τ − m) + w_wrong·wrongShare
         + w_dead·urgency(section) + w_seq·(1 − position/total)
```

- base: REVIEW 1,0; RETRY_TEST 0,9; NEXT 0,8; SKIP_AHEAD 0,6 (+ (m − ρ)); CHALLENGE 0,4; DEADLINE 1,1·urgency;
- w_gap = 2,0 — «прогалина» до порогу засвоєння;
- w_wrong = 0,3 — частка помилок в останній спробі тесту уроку;
- w_dead = 0,6, urgency = 1 − днів_до_дедлайну / 7 (0, якщо дедлайну немає);
- w_seq = 0,2 — ближчі до початку курсу кроки трохи важливіші.

Кожна рекомендація має стабільний ключ `TYPE:ціль`, причину (ключ i18n) і параметри — інтерфейс пояснює студенту, *чому* її запропоновано («Тема «HTML» засвоєна на 36 %. Повторіть урок …»). Дублікати за ключем відкидаються, список сортується за пріоритетом, повертається top-N (5 у курсі, 3 на головній).

Псевдокод:

```
для кожної теми s:
    рівень ← level(m_s, n_s)
    якщо рівень = слабка:
        для 2 уроків теми (за часткою помилок): додати REVIEW
        якщо є тест: додати RETRY_TEST
    якщо рівень = засвоєна:
        якщо є незавершені уроки: додати SKIP_AHEAD
        якщо є тест: додати CHALLENGE
    для кожного незданого дедлайну ≤ 7 днів: додати DEADLINE
перший незавершений урок, перед яким немає слабких тем → NEXT
унікалізувати за ключем; сортувати за priority ↓; взяти top-N
```

## 4. Адаптивне формування тесту

Якщо тест позначено адаптивним (або так задано за замовчуванням у курсі), на старті спроби питання добираються під рівень студента. Цільова складність для бажаної імовірності правильної відповіді p* = 0,7:

```
b* = θ − ln(p* / (1 − p*))  ≈ θ − 0,847
```

Пул — власні питання тесту + усі питання прив’язаних категорій банку; розмір спроби — як у звичайній (`questionsPerAttempt` + правила банку). Вартість питання:

```
cost(q) = |b_q − b*| + 1,0·[q було в попередній спробі] − 0,5·[тема q слабка] + ε
```

Спершу береться найкраще питання кожної слабкої теми, далі — найдешевші. Якщо набір збігся б із попередньою спробою, а в пулі є інші питання, найдорожче з обраних замінюється найкращим невикористаним. Стратегія (`ADAPTIVE`/`FIXED`) і b* зберігаються у `TestResult`; подія `ADAPTIVE_TEST_GENERATED` фіксує θ, b* і обрані питання.

## 5. A/B-експеримент

У налаштуваннях курсу викладач вмикає режим `AB_TEST`:

- усі активні студенти випадково й порівну діляться на групи ADAPTIVE і CONTROL (перемішування Фішера–Єйтса, |A − C| ≤ 1);
- новий студент під час експерименту потрапляє в меншу групу (за рівності — випадково);
- **CONTROL** отримує неадаптивну поведінку: без рекомендацій і з фіксованими тестами (перевіряється на сервері);
- модель засвоєння ведеться для обох груп — для порівняння.

Експорт CSV (`/courses/:id/adaptive/experiment/export`) — анонімізовано (S01, S02…): група, pre_score (перша спроба першого тесту), post_score (остання спроба останнього тесту), приріст, середній бал, кількість адаптивних спроб, середнє засвоєння, кількість слабких тем, θ, % пройдених уроків, днів до завершення, показані/відкриті/виконані рекомендації.

## 6. Журнал подій і метрики рекомендацій

`AdaptiveEvent`: `RECOMMENDATION_SHOWN` (не частіше разу на 6 год для того самого ключа), `RECOMMENDATION_OPENED`, `MASTERY_UPDATED` (до/після, джерело), `ADAPTIVE_TEST_GENERATED`.

Рекомендацію вважають **виконаною**, якщо протягом 7 днів після першого показу студент завершив урок (REVIEW/NEXT), почав спробу тесту (RETRY_TEST/CHALLENGE), здав роботу (DEADLINE) або відкрив пораду SKIP_AHEAD.

Міграція: `20261114120000_adaptive_learning`.

## 8. Інтеграція

Модель оновлюється з доменних подій: завершення спроби тесту (`TestsService.submitTest`), ручна оцінка есе, оцінка лабораторної (`AssignmentsService.grade`), завершення уроку (`LessonsService`/`ProgressService`). Помилки модуля адаптації логуються й не переривають основний сценарій.

## 9. Параметри

Усі параметри — в одному об’єкті `ADAPTIVE_CONFIG` (`adaptive.algorithm.ts`): α, ваги доказів, коефіцієнти складності, b₀, параметри Ело, p*, пороги, мінімум доказів, top-N, горизонт дедлайнів, ваги пріоритету. Пороги τ і ρ викладач змінює в налаштуваннях курсу.
