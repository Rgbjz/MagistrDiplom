# Протокол пілотного A/B-експерименту з реальними студентами

Протокол доповнює імітаційне дослідження ([`../experiment.md`](../experiment.md)). Його мета — перевірити ефект модуля адаптації на реальних учасниках, використовуючи A/B-режим, уже вбудований у LMS. Протокол — план. Поки пілот не проведено, в роботі не можна наводити жодних результатів реальних студентів.

## 1. Учасники та етика

- **Хто:** добровольці, 10–40 осіб, наприклад студенти групи або знайомі без досвіду теми курсу. Що більше учасників, то надійніший висновок; за n < 10 у групі результат лише розвідувальний.
- **Згода:** перед стартом кожен отримує коротке пояснення, підписує письмову або електронну згоду і може вийти з дослідження будь-коли.
  - **Що пояснюється:** мету, що збираються лише навчальні дії в LMS, що результати аналізуються анонімно і що участь добровільна.
- **Анонімність:** експорт LMS містить лише коди S01, S02, … без імен та email. Ніяких персональних даних поза LMS не збирається.
- **Тривалість:** 1–2 тижні, 3–5 годин навчання на учасника.

## 2. Підготовка курсу на сайті

1. **Курс.** Взяти курс «HTML з нуля (відеокурс)» або інший з кількома розділами, у кожному з яких є тест.
2. **Вхідний тест.** Додати у перший розділ коротке тестування (8–10 питань з усіх тем). Він фіксує початковий рівень, і його результат потрапляє в стовпець `pre_score`.
3. **Підсумковий тест.** Додати в останній розділ підсумкове тестування з іншими, але рівноцінними питаннями (10–15). Його результат потрапляє в стовпець `post_score`, приріст — у `gain`.
4. **Налаштування адаптації.** У «Керування курсом → Адаптація»:
   - увімкнути адаптацію;
   - пороги залишити за замовчуванням (60 % і 85 %);
   - увімкнути «Адаптивні тести за замовчуванням»;
   - режим експерименту — **A/B**, зберегти.

   Студенти, що вже записані, автоматично й порівну розподіляються між групами ADAPTIVE і CONTROL. Нових учасників система додає в меншу групу.
5. **Перевірка налаштувань.** Під тестовим студентом переконатися, що контрольна група не бачить рекомендацій, а адаптивна — бачить.

## 3. Проведення

1. Учасники реєструються. Поки немає SMTP, адміністратор підтверджує email кнопкою «Підтвердити email». Потім учасники записуються на курс.
2. Усі складають вхідний тест у перший день.
3. Учасники навчаються в зручному темпі. Інструкція однакова для обох груп: «пройдіть курс до кінця, користуйтеся всім, що пропонує сторінка курсу». Про групи учасникам не повідомляють.
4. У кінці всі складають підсумковий тест.
5. Викладач не втручається вибірково: однакові оголошення для всіх, відповіді в чаті — однаково для обох груп.

## 4. Збір даних

«Керування курсом → Адаптація → Експорт результатів (CSV)» (`GET /api/courses/:id/adaptive/experiment/export`). Стовпці:

| Стовпець | Значення |
|---|---|
| `student` | анонімний код |
| `group` | ADAPTIVE / CONTROL |
| `pre_score` / `post_score` / `gain` | вхідний / підсумковий тест, % / приріст |
| `avg_last_score`, `tests_taken`, `adaptive_attempts` | тести |
| `mean_mastery`, `weak_sections`, `theta` | модель студента |
| `lessons_completed_pct`, `days_to_complete` | прогрес |
| `rec_shown`, `rec_opened`, `rec_followed` | рекомендації: показано, відкрито, виконано |

## 5. Аналіз

Той самий статистичний код, що й у моделюванні:

```bash
cd backend
npm run sim:analyze -- --input ~/Downloads/experiment.csv                # gain, post_score, mean_mastery, lessons_completed_pct
npm run sim:analyze -- --input ~/Downloads/experiment.csv --metric gain  # одна метрика
```

Для кожної метрики виводяться середні груп, різниця, Cohen's d з 95 % ДІ (бутстреп), p-значення t-критерію Велча і U-критерію Манна–Вітні.

- **Первинна метрика:** `gain`. Вторинні: `post_score`, `lessons_completed_pct`.
- **Рішення:** перевага адаптації підтверджується, якщо d > 0, а 95 % ДІ не містить 0.
- **Мала вибірка.** За малої вибірки, як очікується, звітувати розмір ефекту з ДІ, а не лише p-значення. Висновок формулювати як попередній.

## 6. Що звітувати в роботі

1. Кількість учасників у групах і кількість тих, хто вибув.
2. Порівнянність груп за `pre_score`.
3. Таблицю метрик із d [95 % ДІ] і p.
4. Частку виконаних рекомендацій (`rec_followed / rec_shown`).
5. Обмеження: мала вибірка, добровольці, короткий термін, не сліпий для викладача.

Результати пілота порівнюються з прогнозом моделювання (розділ 6 [`../experiment.md`](../experiment.md)). Розбіжність — привід уточнити параметри моделі.
