# Лендинги курсов + цена + мок-покупка — дизайн (подпроект B)

**Дата:** 2026-05-31
**Статус:** утверждён (дизайн), ожидает ревью спецификации

## 1. Цель и контекст

Превратить платформу в «онлайн-школу» (как Kwiga): публичные **продающие страницы курсов**, **цена** (free/paid) и **мок-покупка** (без реальной оплаты). Это **подпроект B** апгрейда (после A — дизайн-система + кабинет). Дальше — C (мок-подтверждение email).

Разбит на два плана: **B1** (данные + бэкенд) → **B2** (фронтенд).

## 2. Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Доступ к лендингу | **Публичный** (без входа), как Kwiga. Покупка/запись — после входа |
| Модель доступа | **Платный** курс: «купить» → мок-оплата успешна → сразу `ACTIVE` (без одобрения). **Бесплатный**: как сейчас — заявка → одобрение преподавателем |
| История покупок | Таблица `Payment/Order`; вход в историю — **кнопка в профиле** (не в хедере) |
| Состав лендинга | Hero (обложка, цена, CTA) · описание · программа (разделы/уроки — закрытые, без превью-просмотра) · преподаватель |
| Валюта | `$` (хардкод, мок) |
| Превью-уроки | Нет (вне скоупа, чтобы не раздувать) |

## 3. Модель данных (Prisma)

- **`Course.price`** — `Int @default(0)`. Целые единицы `$`. **0 = бесплатный**, `>0` = платный.
- **`Payment`** (новая таблица): `id Int @id`, `userId Int`, `courseId Int`, `amount Int`, `status String @default("PAID")`, `createdAt DateTime @default(now())`, связи `belongsTo` User и Course (`onDelete: Cascade`).

Миграция Prisma добавляет поле и таблицу.

## 4. Бэкенд (эндпоинты)

- **`GET /api/public/courses/:id`** — **без `JwtAuthGuard`** (публично). Возвращает `{ id, title, description, imageUrl, price, teacher: { name }, sections: [{ title, lessons: [{ title, hasTest }] }] }`. Только заголовки уроков (без контента). `teacher.name` = `firstName lastName` или email. 404 если курса нет.
- **`GET /api/courses/:id/my-status`** (auth) → `{ enrollmentStatus: 'PENDING'|'ACTIVE'|'REJECTED'|'COMPLETED' | null }` для текущего пользователя.
- **`POST /api/courses/:id/purchase`** (auth, роль STUDENT) — мок-покупка. Если `course.price <= 0` → `400 'Course is free'`. Иначе: создаёт `Payment { userId, courseId, amount: price, status: 'PAID' }` и upsert `Enrollment` в `status: 'ACTIVE'` (без одобрения). Идемпотентно (если уже ACTIVE — не дублировать платёж: проверка существующей ACTIVE-записи → 400 'Already purchased'). Возвращает `{ ok: true }`.
- **`GET /api/me/purchases`** (auth) → `[{ id, amount, status, createdAt, course: { id, title, imageUrl } }]` для текущего пользователя, новые сверху.
- **Цена курса:** `CreateCourseDto`/`UpdateCourseDto` получают необязательное `price?: number` (`@IsInt @Min(0)`); `CoursesService.create/update` сохраняют `price` (по умолчанию 0). `price` добавляется в выборку листинга курсов (`getCoursesForUser`, `CourseListItem`).

Модули: новый `PublicModule` (или `PaymentsModule`) для публичного эндпоинта и покупок/истории, переиспользует `PrismaService`. Бесплатная запись — существующий `POST /api/courses/:id/enroll`.

## 5. Фронтенд

- **Публичный лендинг `/c/[id]`** — серверный компонент; тянет `GET /api/public/courses/:id` **без токена** (server fetch). Рендерит hero (обложка/градиент, заголовок, описание, преподаватель, карточка цены: «Бесплатно» или «$X»), описание, программу (разделы→уроки/тесты, иконка 🔒). Middleware пропускает `/c/...` без авторизации.
- **CTA-кнопка** (клиентский компонент) на лендинге — по `useSession` + (если вошёл) `GET /api/courses/:id/my-status`:
  - не вошёл → «Войти, чтобы продолжить» → `/login`;
  - платный, не куплен → «Купить за $X» → `/checkout/[id]`;
  - бесплатный, не записан → «Записаться» (`POST /enroll`, тост «Заявка отправлена»);
  - `ACTIVE` → «Перейти к курсу» → `/courses/:id`; `PENDING` → «Заявка на рассмотрении» (disabled).
- **Мок-чекаут `/checkout/[id]`** (auth) — карточка курса + цена + фейковая форма карты (номер/срок/CVC — любые значения, без валидации платёжки) + кнопка «Оплатить $X» → `POST /purchase` → тост успеха → редирект `/courses/:id`. Оплата всегда успешна.
- **Цена в конструкторе** — поле «Цена ($), 0 = бесплатно» в `CreateCourseForm` (FormData `price`) и в настройках `CourseBuilder` (PATCH курса с `price`).
- **История покупок `/purchases`** (auth) — список заказов (курс, сумма, дата) из `GET /api/me/purchases`. Вход — **кнопка «Мои покупки» в профиле**.
- **Бейдж цены** на `CourseCard` и в каталоге: «Бесплатно»/«$X». Для платных не-записанных студентов основная кнопка ведёт на лендинг `/c/:id` (или сразу на чекаут).

UI на дизайн-системе подпроекта A (UI-кит, токены, тёмная тема).

## 6. Вне скоупа подпроекта B

- Реальная платёжная интеграция (Stripe и т.п.) — оплата мок.
- Превью-уроки на лендинге.
- Промокоды, скидки, тарифы/подписки, рассрочка.
- Выручка преподавателя/аналитика продаж (можно позже на данных `Payment`).
- Возвраты.

## 7. Критерии готовности

- Курс имеет цену; преподаватель задаёт её при создании/в конструкторе; 0 = бесплатный.
- Лендинг `/c/:id` открывается **без входа** и показывает hero/описание/программу/преподавателя/цену.
- CTA корректно ветвится (войти / купить / записаться / перейти / на рассмотрении).
- Платный курс: чекаут → мок-оплата → мгновенный `ACTIVE` + запись `Payment(PAID)`; повторная покупка отклоняется.
- Бесплатный курс: «Записаться» → `PENDING` (существующий флоу одобрения).
- История покупок доступна из профиля и показывает заказы.
- Каталог/карточки показывают цену; всё в теме A (светлая/тёмная).
